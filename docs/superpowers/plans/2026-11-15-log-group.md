# Группа отладки и логов — план

> Исторический документ: написан в ходе работы на документах реального объекта, которых в репозитории нет.
> Номера актов, объёмы и названия обезличены; счётчики вроде «63 акта» относятся к тем документам,
> а не к синтетическим примерам из `examples/`.

**Цель:** бот пишет в выбранную Telegram-группу по одному сообщению на каждое обработанное действие, чтобы владелец и инженер видели, что прислано, что бот ответил и где он ошибся.

**Подход:** очередь действий в `bot.ts` уже одна на всех. На время действия ведётся запись: заголовок (кто и что прислал), вызовы инструментов агента, всё, что бот отправил пользователю, ошибки. Когда действие закончилось, запись уходит в группу одним сообщением. Отправка журнала идёт своей цепочкой и никогда не роняет основную работу.

**Спецификация:** `docs/superpowers/specs/2026-11-14-reestr-agent-design.md`, решения владельца от 15.11.2026: в группе инженер и владелец; входящие файлы пересылать; ошибки показывать.

## Ограничения

- В группе бот только пишет. Единственная команда — `/logs_here` от разрешённого id: привязывает группу. Остальные сообщения группы молча отбрасываются; агент, ядро и файлы из группы недоступны.
- Токен и ключ хаба в журнал не попадают: текст проходит ту же замену токена, что и файл журнала.
- Обычная запись — без звука (`disable_notification`), тревога — со звуком.
- Одна запись — одно сообщение, не длиннее 3900 знаков; длинные куски обрезаются.
- Сбой отправки в группу пишется в файл журнала и не меняет ответ пользователю.
- Новых зависимостей нет. Id группы хранится в `<agentState>/log-chat.json`, вне репозитория.

## Что видит группа

| Событие | Вид | Звук |
|---|---|---|
| Текст, файл, кнопка, команда | кто (имя, id), что прислал, вызовы инструментов с аргументами и итогом, ответы бота | нет |
| Входящий файл | копия самого файла (`copyMessage`) | нет |
| Отправка реестра | кому, сколько актов | нет |
| Запуск и остановка | коммит, число актов и вопросов | нет |
| Внутренняя ошибка, модель не ответила | текст ошибки | да |
| Чужой написал боту | имя, id | да |

## Задачи

### 1. Журнал (`bot/src/audit.ts`, `bot/test/audit.test.ts`)

- `createAudit(api, {file, log, clean, retryPauseMs?}): Audit`
- `Audit { chatId(): number | undefined; bind(id: number): void; post(text: string, opts?: {alarm?: boolean}): void; copy(fromChat: number, messageId: number): void; idle(): Promise<void> }`
- Тесты: без привязки ничего не шлёт; `bind` переживает перезапуск; запись обрезается до 3900; тревога без `disable_notification`; ошибка Telegram не бросается наружу, 429 повторяется один раз.

### 2. Вызовы инструментов в ходе агента (`bot/src/tools.ts`, `bot/src/agent.ts`)

- `Turn.calls: {name: string; args: unknown; result: string; ms: number}[]`; `result` — `ok`, статус (`needs_confirmation`, `needs_button`) или `ошибка <code>: <message>`.
- `AgentReply.failure?: string` — причина, по которой модель не ответила.
- Тест: вызов с успехом и вызов с ошибкой ядра попадают в `calls`.

### 3. Подключение к боту (`bot/src/bot.ts`, `bot/src/main.ts`, `bot/test/bot.test.ts`)

- `BotDeps.logChatFile?: string`; `AosrBot.audit`.
- `enqueue(chatId, head, job)`; `send`, `edit`, `report`, `sendRegistry` дописывают текущую запись.
- Промежуточное звено доступа: группа → только `/logs_here`; чужой в личке → тревога.
- `main.ts`: записи о запуске (с коротким хешем коммита) и остановке.
- Тесты: привязка владельцем и отказ чужому; текст в группе не доходит до агента; ход с инструментами даёт одну запись со всеми частями; файл копируется; внутренняя ошибка — тревога без токена; чужой — тревога; сбой журнала не ломает ответ.

### 4. Проверка и выкладка

- `npx vitest run`, `npx tsc --noEmit`, `.venv/bin/pytest -q`.
- README: раздел про группу логов. Перезапуск службы; владелец пишет в группе `/logs_here`.
